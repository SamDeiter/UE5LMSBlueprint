# How‑To Guide: Need‑Node Validation & GUID System

---

## 1. Overview
The **Need‑Node** lets you embed assessment criteria directly in a Blueprint graph. When a simulation runs, the node validates the graph against the defined rules and reports a pass/fail result (also sent to SCORM).  GUIDs (UUID v4) uniquely identify every node and wire, ensuring global uniqueness and reliable persistence.

---

## 2. Adding a Need‑Node
1. Open the Blueprint editor (`http://localhost:8080`).
2. In the **Assessment** panel, drag **Need Node** onto the canvas.
3. The **Need‑Node modal** opens automatically (or double‑click the node to edit).

![Need‑Node modal](C:/Users/Sam%20Deiter/.gemini/antigravity/brain/a7f9a729-5244-495c-acd4-2aceb7574bf9/need_node_modal_1764098886286.png)

### Basic fields
- **Title** – displayed on the node header.
- **Description** – optional explanatory text.
- **Pass Threshold** – % of criteria that must pass.
- **Hidden** – hide criteria from the UI (useful for internal checks).

## 3. Structured Validation Rules
Click **Add Criterion** to create a new rule.

![Add Criterion row](C:/Users/Sam%20Deiter/.gemini/antigravity/brain/a7f9a729-5244-495c-acd4-2aceb7574bf9/new_criterion_row_1764098896846.png)

### 3.1 Validator Types & Parameters
| Type | Description | Dynamic Parameters |
|------|-------------|--------------------|
| **NODE_EXISTS** | Verify that a node of a given type exists. | **Node Type** (text), **Minimum Count** (number) |
| **PIN_CONNECTED** | Ensure a specific pin on a node is connected. | **Node Type** (text), **Pin ID** (text) |
| **VARIABLE_VALUE** | Check a variable’s value against an operator. | **Variable Name** (dropdown of defined variables), **Expected Value** (text), **Operator** (==, !=, >, <) |
| **COMPONENT_EXISTS** | Confirm a component of a given type/name exists in the blueprint. | **Component Type** (text), **Component Name** (text) |

When you select a validator, the appropriate fields appear automatically.

![Node Exists parameters](C:/Users/Sam%20Deiter/.gemini/antigravity/brain/a7f9a729-5244-495c-acd4-2aceb7574bf9/node_exists_params_1764098927251.png)

### 3.2 Data Structure
Each criterion is saved as:
```json
{
  "id": "criterion-0",
  "type": "NODE_EXISTS",
  "params": { "nodeKey": "PrintString", "count": 1 },
  "description": "At least one PrintString node must exist",
  "passed": false
}
```
The modal’s **Save** button collects all rows into an array and stores it on the node.

## 4. GUID System
- GUIDs are generated by `utils/guid.js` using `crypto.randomUUID()` (fallback to a UUID‑v4‑like string).
- **Node creation** – `GraphController.addNode` calls `generateGUID()` for the node ID.
- **Link creation** – `WiringController._addLink` now uses `generateGUID()` for link IDs.
- GUIDs appear in the saved graph JSON, ensuring each element is uniquely addressable across sessions and potential distributed environments.

### Why GUIDs?
- No collision risk, even after many saves/reloads.
- Simplifies debugging (IDs are readable UUIDs).
- Future‑proof for server‑side persistence or multi‑user collaboration.

---

## 5. Running Simulations
1. Click **Run Simulation** (top‑right toolbar).
2. The engine evaluates all Need‑Nodes using `GraphValidator`.
3. Results are shown on the node (green check / red cross) and reported to SCORM.
4. Open the **Details** panel to see which criteria passed or failed.

---

## 6. Example Walkthrough
### Goal: Ensure a `PrintString` node exists and a variable `Score` equals `100`.
1. Add a Need‑Node.
2. **Criterion 1** – Type: `NODE_EXISTS` → Node Type: `PrintString`, Minimum Count: `1`.
3. **Criterion 2** – Type: `VARIABLE_VALUE` → Variable Name: `Score`, Expected Value: `100`, Operator: `==`.
4. Save and run the simulation.
5. The node will turn green only when both conditions are satisfied.

## 7. Best Practices
- **Name criteria clearly** – the description is what the learner sees.
- **Group related checks** in the same Need‑Node for a logical assessment.
- **Use GUIDs** – never edit IDs manually.
- **Keep the variable list tidy** – unused variables clutter the dropdown.
- **Test each validator** in isolation before combining them.

---

## 8. Troubleshooting
| Symptom | Likely Cause | Fix |
|---------|---------------|-----|
| No criteria appear after saving | Modal not refreshed | Close and reopen the node or reload the page. |
| Validation always fails | Wrong validator parameters (e.g., typo in node type) | Verify exact spelling; use the dropdown where available. |
| Duplicate GUID error (rare) | Manual edit of JSON IDs | Never edit IDs; let the system generate them. |
| Pin shows as filled after disconnect | WiringController link not removed | Ensure `breakPinLinks` is called; refresh the canvas (`Ctrl+R`). |
